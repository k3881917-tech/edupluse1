# EduPlus на Netlify

Telegram Mini App: расписание, домашка и оценки из Дневник.ру плюс календарь со своими событиями. Работает целиком на Netlify, без своего сервера и без Python.

```
Telegram ── Mini App (public/index.html, сайт Netlify)
                │ подпись Telegram (initData)
                ▼
     Функция /api/* (netlify/functions/api.mjs) ── Netlify Blobs (данные)
                │ обычные HTTP-запросы
                ▼
     login.dnevnik.ru → dnevnik.ru/api/v2/marks/diary

Каждые 30 минут: netlify/functions/cron.mjs — новые оценки, вечером домашка на завтра
Бот: вебхук /api/tg — /start и /notify
```

## Запуск (5 шагов, ничего ставить на компьютер не нужно)

### 1. Бот
В [@BotFather](https://t.me/BotFather): `/newbot` → сохрани токен.

### 2. Репозиторий на GitHub
Создай пустой репозиторий → **Add file → Upload files** → перетащи туда всё содержимое этой папки (`public`, `netlify`, `netlify.toml`, `package.json`…) → **Commit**.

### 3. Сайт на Netlify
**Add new site → Import an existing project → GitHub** → выбери репозиторий. Настройки сборки менять не нужно, они в `netlify.toml`.

### 4. Переменные окружения
**Site configuration → Environment variables** → добавь:

| Ключ | Значение |
|---|---|
| `BOT_TOKEN` | токен от BotFather |
| `SECRET_KEY` | случайная строка от 32 символов (ключ шифрования паролей; не меняй потом, иначе всем придётся войти заново) |
| `ADMIN_KEY` | любое слово — пароль для шага 5 |
| `HW_REMINDER_HOUR` | *(необязательно)* час напоминания о домашке по Москве, по умолчанию `19` |

После этого **Deploys → Trigger deploy → Deploy site**.

### 5. Подключи бота к сайту
Открой один раз в браузере:

```
https://ТВОЙ-САЙТ.netlify.app/api/setup?key=ТВОЙ_ADMIN_KEY
```

Должны быть три `"ok": true`. Готово: в боте `/start` → «Открыть EduPlus» → вставь ключ входа (инструкция прямо в приложении).

## Вход: ключ вместо пароля

Дневник.ру пускает только через Госуслуги, поэтому EduPlus не просит пароль. Ты входишь на dnevnik.ru сам, копируешь строку `cookie` из инструментов разработчика (Network → первый запрос → Request Headers → cookie → Copy value) и вставляешь в приложение или отправляешь боту — бот сразу удаляет это сообщение. Когда ключ устареет, бот напишет.

Если позже поменяешь адрес сайта (свой домен), задай `WEBAPP_URL` с новым адресом и открой `/api/setup` ещё раз.

## Что где

| Файл | Что делает |
|---|---|
| `public/index.html` | само приложение (без Telegram открывается в демо-режиме) |
| `netlify/functions/api.mjs` | API приложения, вебхук бота, `/api/setup` |
| `netlify/functions/cron.mjs` | синхронизация и уведомления по расписанию |
| `netlify/lib/dnevnik.mjs` | вход в Дневник.ру и загрузка дневника |
| `netlify/lib/transform.mjs` | ответ Дневник.ру → формат EduPlus |
| `netlify/lib/sync.mjs` | синхронизация, автоповторный вход, четверти |
| `netlify/lib/store.mjs` | хранение в Netlify Blobs |
| `netlify/lib/crypto.mjs` | шифрование сессии и пароля (AES-256-GCM) |
| `netlify/lib/tgauth.mjs` | проверка подписи Telegram |
| `netlify/lib/tg.mjs` | сообщения бота |

## Если что-то не работает

- **«Ключ не подошёл»** — обнови страницу dnevnik.ru, убедись, что ты вошёл, и скопируй значение `cookie` целиком заново.
- **Не приходят уведомления** — плановые функции работают только на опубликованном (production) деплое. Логи: **Logs → Functions → cron**.
- **Ошибки входа** видны в **Logs → Functions → api**. Пришли текст ошибки — поправим.

## Ограничения

- Неофициальная интеграция: если Дневник.ру поменяет форму входа или API, вход придётся поправить.
- Кабинеты Дневник.ру не отдаёт — их вписывают в приложении («кабинет?» на уроке).
- Веса оценок API не отдаёт, средний — обычный, как на странице «Рейтинг».
- Границы четвертей примерные.
- Если даёшь приложение друзьям, предупреди: их ключ входа в Дневник.ру хранится на твоём Netlify в зашифрованном виде.
